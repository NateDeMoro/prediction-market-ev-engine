# plus-ev-bot — file index for the agent

A multi-book +EV scanner for U.S.-legal sports prediction markets. Pinnacle is the sharp anchor; soft books (Kalshi, Polymarket US) are scanned for stale-line opportunities in the 0.5-3h pregame window. Paper-trades and (as of 2026-04-30) auto-places real money.

## Working environment

All production data, logs, and live state are on the VPS:

```
ssh arb@ev-betting-bot
cd ~/Arbitrage_Betting
```

The local repo at `/Users/natedemoro/Code_Desktop/plus-ev-bot/` is for editing code only. Local `data/` is stale dev fixtures — never reason about real trading state from local files. When inspecting trades, fills, settlements, balances, or service logs, SSH into the VPS first. Code changes ship to the VPS via scp and a `systemctl restart` of the affected unit.

Restart is passwordless via this exact command (sudoers rule pins the unit list):

```
ssh arb@ev-betting-bot 'sudo -n /bin/systemctl restart pinnacle-poller kalshi-poller polymarket-poller ev-dashboard'
```

Single-unit restarts will prompt for a password and fail.

## Key conventions

- Soft-book market_id format: Kalshi uses raw ticker; Polymarket uses `{slug}:{long\|short}`.
- side ∈ {"yes","no"}; for Polymarket, the bet side translates to the underlying market via XOR with the long/short suffix.
- All placement records carry `(book, market_id, side)` as their dedup key.
- State files are append-only JSONL; replay-on-import rebuilds in-memory state.
- Real-money trading is gated on `REAL_TRADING_ENABLED=1`; off by default.
- Placement statuses: `dry_run` / `pending` / `partial` / `filled` / `error` / `ambiguous`. `ambiguous` = order may have reached broker (timeout / 5xx); stake stays deducted, dedup key retained, no auto-poll (no order_id). Operator reconciles via broker UI.
- All stored prices (avg_fill_price, fair_prob_close, clv) are in the **internal side perspective** — i.e. cost-per-share for the side bought. Polymarket's API returns prices in long-side perspective and must be flipped when api_side="no" before storage. Migration scripts in `scripts/` exist for fixing past corruption.
