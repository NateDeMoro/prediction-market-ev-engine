Arbitrage Betting — Operating Instructions
==========================================

Four long-running processes power the pipeline. Each is started under
`nohup` and tracked by its own pid file under `data/`. The paper-bet
tracker has no separate process; it runs as background threads inside
`ev_dashboard.py`.

Services
--------
  pinnacle_poller.py     60s Pinnacle odds poller (sharp fair source).
  kalshi_poller.py       60s Kalshi sports-markets poller.
  polymarket_poller.py   60s Polymarket US leagues poller.
  ev_dashboard.py        Flask UI on http://127.0.0.1:5055; owns the
                         paper-bet tracker + settlement + CLV threads.
  server.py              AZ Sportsbook Promo Dashboard on http://<host>:8080
                         (index.html + state.json). Unrelated to the EV
                         pipeline; used for matched-betting promo tracking.

File conventions per service
----------------------------
                         pid file              rolling log           stdout log
  pinnacle_poller.py     data/poller.pid       data/pinnacle.log     data/stdout.log
  kalshi_poller.py       data/kalshi.pid       data/kalshi.log       data/kalshi_stdout.log
  polymarket_poller.py   data/polymarket.pid   data/polymarket.log   data/polymarket_stdout.log
  ev_dashboard.py        data/dashboard.pid    data/dashboard.log    data/dashboard.log
  server.py              data/promo.pid        —                     data/promo.log

All commands below assume you are in the project root:
    cd /Users/natedemoro/Code_Desktop/Arbitrage_Betting

Prerequisites
-------------
- Python 3 with `requests` and `flask` installed.
- Mac mini should not sleep on AC power:
      pmset -g | grep -E "^ sleep| disksleep"
  Both should read 0. If not:
      sudo pmset -c sleep 0 disksleep 0


Pinnacle poller
---------------
Start:
    nohup python3 pinnacle_poller.py > data/stdout.log 2>&1 &
    echo $! > data/poller.pid

Status:
    ps -p $(cat data/poller.pid)
    tail -f data/pinnacle.log

Stop (graceful; force-kill with -9 if it hangs):
    kill $(cat data/poller.pid) && rm data/poller.pid

EV dashboard (+ paper tracker)
------------------------------
The dashboard serves the UI on http://127.0.0.1:5055 and runs the
paper-bet placement, settlement, and CLV-capture threads in the same
process. Stopping the dashboard stops paper tracking too.

Start:
    nohup python3 ev_dashboard.py > data/dashboard.log 2>&1 &
    echo $! > data/dashboard.pid

Status:
    ps -p $(cat data/dashboard.pid)
    tail -f data/dashboard.log
    open http://127.0.0.1:5055

Stop:
    kill $(cat data/dashboard.pid) && rm data/dashboard.pid


Promo dashboard (server.py)
---------------------------
Serves index.html + a LAN-synced bet state via state.json. Standalone
from the EV pipeline; safe to run or stop independently.

Start (background, reachable on LAN):
    nohup python3 server.py > data/promo.log 2>&1 &
    echo $! > data/promo.pid

Foreground alternative (Ctrl-C to stop):
    python3 server.py

Access:
    http://localhost:8080              this machine
    http://<lan-ip>:8080               other devices on the same WiFi

Status:
    ps -p $(cat data/promo.pid)
    tail -f data/promo.log

Stop:
    kill $(cat data/promo.pid) && rm data/promo.pid


Start / stop all
----------------
Start everything (order does not matter, but pollers should be up before
the dashboard shows meaningful data). The promo dashboard is included
for convenience; omit the last line if you don't need it running.

    nohup python3 pinnacle_poller.py   > data/stdout.log            2>&1 & echo $! > data/poller.pid
    nohup python3 kalshi_poller.py     > data/kalshi_stdout.log     2>&1 & echo $! > data/kalshi.pid
    nohup python3 polymarket_poller.py > data/polymarket_stdout.log 2>&1 & echo $! > data/polymarket.pid
    nohup python3 ev_dashboard.py      > data/dashboard.log         2>&1 & echo $! > data/dashboard.pid
    nohup python3 server.py            > data/promo.log             2>&1 & echo $! > data/promo.pid

Stop everything:

    for p in poller kalshi polymarket dashboard promo; do
        [ -f data/$p.pid ] && kill $(cat data/$p.pid) && rm data/$p.pid
    done

Health check across all services:

    for p in poller kalshi polymarket dashboard promo; do
        [ -f data/$p.pid ] && ps -p $(cat data/$p.pid) -o pid,command= || echo "$p: not running"
    done


Recovering from a missing or stale pid file
-------------------------------------------
If a `.pid` file is missing or points at a dead process, find the live
one by name:

    pgrep -f pinnacle_poller.py
    pgrep -f kalshi_poller.py
    pgrep -f polymarket_poller.py
    pgrep -f ev_dashboard.py
    pgrep -f server.py

Write the PID back to the corresponding pid file, or kill the orphan
process with `kill <pid>` and restart clean.


Restart after code changes
--------------------------
Stop the affected service, then re-run its Start block. Example for the
Pinnacle poller:

    kill $(cat data/poller.pid) && rm data/poller.pid
    nohup python3 pinnacle_poller.py > data/stdout.log 2>&1 &
    echo $! > data/poller.pid


Outputs and disk usage
----------------------
Snapshot directories (one JSONL per cycle, auto-pruned to the most
recent 60 files ≈ last hour by each poller):

    data/snapshots/              Pinnacle
    data/kalshi_snapshots/       Kalshi
    data/polymarket_snapshots/   Polymarket

Paper-tracker output (append-only):

    data/paper_trades.jsonl       placed bets
    data/paper_settlements.jsonl  settled bets with P&L
    data/paper_closes.jsonl       Pinnacle closing fair prob for CLV

Snapshot retention is handled in-process. If rolling logs grow too
large, truncate them during a stopped window:

    : > data/pinnacle.log
    : > data/kalshi.log
    : > data/polymarket.log
    : > data/dashboard.log


Known limitations
-----------------
- No auto-restart on crash or reboot. For persistence across reboots,
  migrate to launchd per-service.
- If Pinnacle rotates their X-API-Key, cycles will start returning
  HTTPError 401. Grab the current key from devtools on pinnacle.com and
  update API_KEY in pinnacle_poller.py.
- US IP access to Pinnacle works today but could be geoblocked without
  notice. If all cycles fail with 403, route traffic through a VPN.
- Kalshi unauthenticated rate limit is ~2 req/sec; the poller caps at 3
  workers with 429 backoff. Don't raise MAX_WORKERS without testing.
- Polymarket read pipeline uses the public gateway (no auth). Live
  order placement would require POLYMARKET_US_KEY_ID / _SECRET from
  .env.example.
